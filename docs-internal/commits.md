# 提交信息约定（personal fork 的 `local` 分支）

<!-- 本文件只存在于 personal fork 的 local 分支，不属于上游 wezterm -->

这个仓库的读者首先是作者自己，其次是**接手修改的 AI 助手/协作者**。所以标题沿用
上游的 `<area>: <一句话>` 骨架，正文用中文写清楚“为什么”。

## 格式

```
<area>: <一句话，中文，说清改了什么>

原因：现象 + 根因（能引用的行号、实测数据、上游行为都放这里）。
处理：具体怎么改的，以及为什么选这种做法而不是另一种。
验证：跑了什么、结果如何（单测名、真机用例、md5、耗时）。
```

- `area` 用**英文**、小写、冒号后一个空格：取模块路径或功能名
  （`mux`、`config`、`docs`、`zmodem`、`keyword`、`snippet`、`gui`…）。
  好处：`git log --oneline` 能按前缀扫视，`--grep 'zmodem:'` 照样可用，
  将来要提上游时也只需重写正文。
- 标题不加句号，不写 `[WIP]`、不加 emoji。
- 正文每段一行 80 列内换行，段落间空一行；不要整段一行拉到底。
- 一次提交只做一件事。代码与其专门的文档改动可以同在一个提交里；如果文档是
  事后补的（或跨多个功能），单独一个 `docs:` 提交。

## 术语（保持一致，别在不同提交里混用）

| 概念 | 用词 |
|---|---|
| ZMODEM 传输方向 | **上传**（本地 → 远端 `rz`）、**下载**（远端 `sz` → 本地） |
| ZMODEM 数据单元 | **子包**（subpacket）、**帧**（frame） |
| 流量控制 | **窗口**（window）、**确认**（ZACK） |
| 用户中止 / 对端中止 | **取消**（cancelled / CAN） |
| 超时 | **静默超时**（stalled）、**超时**（timed out） |
| 远端程序 | 直接写 `rz` / `sz`，不译成“接收端/发送端” |

## 例外：还是用英文

- 直接要提上游的提交、`Revert "..."`（引用体保持原文）、引用上游 issue/提交号；
- 纯机械改动（`cargo fmt`、版本号 bump、依赖升级）可以只写一行英文标题。

## 不要做的

- 不要为了“统一语言”去改写已经 push 出去的历史（rebase / force-push）；
  语言切换从下一条提交开始，已有的英文提交保留原样。
- 提交前先跑 `cargo fmt`（本仓库要求 `cargo +nightly fmt` 也可）与相关测试，
  正文里的“验证”一栏要写真实跑过的命令和结果，不写“应该可以”。
